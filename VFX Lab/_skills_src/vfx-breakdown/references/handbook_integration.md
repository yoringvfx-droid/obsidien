## 1. 반영 원칙

- **확인 후 적용.** 반영안 표를 먼저 보여주고, 사용자가 승인한 행만 적용한다. 사용자가 빼거나 고친 행은 그대로 따른다.
- **원본 이론 노트(`Lecture/`)는 건드리지 않는다.** 바뀌는 곳은 핸드북 카드, 장 노트, 목차, 사례 카드뿐이다.
- **한 근거는 가장 잘 맞는 카드 하나에.** 여러 카드에 같은 근거를 뿌리지 않는다(연결이 필요하면 카드의 `연결`에 링크).
- **반영 유형은 여덟 가지다.**
  - `보강`: 기존 원리를 다른 수치로 다시 확인. 실측 근거에 한 줄 추가.
  - `반례`: 기존 원리와 다르게 했는데도 잘 작동한 사례. `충돌·주의`에 "출처 A는 …, 이 사례는 … → 정리: …" 형식으로 추가. 원리를 바꾸지는 않는다.
  - `신규`: 기존 카드 어디에도 맞지 않는 원리. 새 카드를 만든다. 사례 하나로만 나온 원리는 카드 원리 아래에 "실측 사례 1건에서 나온 원리"라고 적는다.
  - `실패`: 평가의 weak 항목. 원리를 어겨서 실제로 약해진 사례. 해당 카드 `충돌·주의`에 "이렇게 하면 약해진다: … (사례, 프레임) → 개선: …" 한 줄.
  - `주의`: 평가의 risk 항목. 게임에 가져올 때의 위험. 해당 카드 `충돌·주의`에 "게임 적용 주의: … → 대응: …" 한 줄.
  - `사례`: 09 부록에 사례 카드(`APnn 사례 — <원제>`)를 하나 만든다. 매번 1장. 총평 한 줄과 그대로 / 바꿔서 / 쓰지 않는다 표를 포함한다.
  - `유형`: `10 유형/`의 유형 노트(예: 투사체 — 유형 노트)의 사례 비교 표에 이 사례 열을 더하고, 범위가 바뀐 렌즈 숫자를 고친다. 유형 노트의 정리를 뒤집으면 그 렌즈에 "반례:" 한 줄. 새 유형이면 노트를 새로 만들고 `10 유형.md` 표와 목차에 추가한다.
  - `정정`: 기존 카드의 실측 근거가 재측정과 어긋날 때. 해당 근거 줄을 고친다.
- 평가 kind와 반영 유형 대응: good → 보강, counter → 반례, weak → 실패, risk → 주의.
- 평가 항목을 카드에 옮길 때는 한 줄로 줄이되 **수치와 목표값을 남긴다**: 실패는 "관찰 수치 → 개선 목표", 주의는 "게임 조건 → 대응", 반례는 "어긴 원리 · 작동 조건 · 예외 경계". 가져오기(take) 문장은 카드 `## 규칙`에 넣지 않는다(사례 하나로 규칙을 바꾸지 않는다). 같은 내용이 두 번째 사례에서 나오면 그때 규칙 추가를 제안한다.
- 평가가 기존 카드의 실측 근거와 어긋나면(예: 카드에는 HSV S로 "채도가 내려갔다"고 적혀 있는데 선명도는 오른다) 반영안 표에 유형 `정정`으로 올린다. 승인되면 기존 근거 줄을 고치고 끝에 "(정정: <사례> 재측정)"을 붙인다.
- 프레임 수를 카드에 넣을 때는 사례의 fps와 초를 같이 쓴다(예: "39f · 60fps · 0.65s"). 기존 星光啊 수치는 30fps다.
- 카드 목록은 실제 볼트를 읽어서 확인한다(`ls`, 각 카드의 `> [!abstract] 원리` 줄). 기억으로 카드 이름을 쓰지 않는다.

## 3. 적용 방법

**보강**
- 카드의 `## 실측 근거` 섹션 끝에 한 덩어리를 추가한다:
  ```markdown
  - **<원제>**: <프레임·수치 한 줄>. ([[<원제 폴더명> - Index]] · <코드>)
  ```
- 카드에 `## 실측 근거`가 없으면 `## 규칙` 다음, `## 충돌·주의`(없으면 `## 체크`) 앞에 새로 만든다.
- frontmatter `evidence: [...]`에 코드를 추가한다.
- 카드 `## 출처` 끝에 `- 실측: [[<원제 폴더명> - Index]] · <코드>` 한 줄.
- 그림은 정말 필요한 카드에만 `![[<그림>|640]]` 1장.

**반례 · 실패 · 주의**: `## 충돌·주의`에 한 줄씩 추가(없으면 `## 체크` 앞에 만든다). 앞에 `반례:` `실패:` `게임 적용 주의:`를 붙여 구분한다. evidence와 출처는 보강과 같다.

**신규 카드**: 4절 양식. 그리고
- 해당 장 노트 표(`| ID | 카드 | 한 줄 원리 |`)에 행 추가, 표 아래 카드 끼워 넣기 `---` + `![[파일명]]` 추가(장 노트의 다른 카드와 같은 형식).
- 목차 `VFX Handbook v2.md`의 "한눈에 보는 원리" 해당 장 목록에 `- **[[파일명|ID]]** <원리> \`신규\`` 추가.
- `체크리스트.md`의 해당 장에 `### ID 제목` + `![[파일명#체크]]` 추가.
- ID는 그 장의 마지막 번호 + 1.

**사례 카드**: `09 부록/APnn 사례 — <원제>.md`. 구조는 기존 `AP02 사례 — 星光啊 闪爆他`를 읽고 그대로 따른다(막 표 + 핵심 원리 + 연결에 근거를 받은 카드 전부). 09 부록 장 노트·목차·체크리스트에도 위처럼 추가.

## 4. 새 카드 양식

```markdown
---
title: "<ID> <제목>"
id: <ID>
chapter: "<장 번호> <장 이름>"
type: principle
tags:
  - vfx-handbook
  - <shape / value / color / light / timing / composition / check / foundation / appendix>
sources: []
evidence: [<코드>]
---

# <제목>

> [!abstract] 원리
> **<한 줄 원리>**
> 실측 사례 1건에서 나온 원리다.

## 왜
- 2–4개

## 규칙
- 3–7개. 수치·조건 구체적으로

## 실측 근거
- 프레임·수치. 그림 1장

## 체크
- [ ] 1–3줄

## 연결
- [[관련 카드 파일명]] 2–4개

## 출처
- 실측: [[<원제 폴더명> - Index]] · <코드>
```
문체: 한국어 단정형, 짧은 문장, 감탄·이모지·대시 삽입구 없음. 명도 = 지각명도(L\*), 선명도 = 눈에 보이는 채도(C\*), HSV S = 색 선택기 채도. 카드 글에는 명도·선명도·HSV S가라고 쓴다. 파일명에 `:` 금지(대신 ` — `).

## 5. 코어 이론

`VFX Handbook v2/Core/`의 코어 이론 8은 **바뀔 때만 제안한다.** 다음 경우에만 반영안 표 아래에 제안을 적는다.
- 새 사례가 코어 원리 하나를 정면으로 뒤집는다(반례가 원리 자체를 흔듦).
- 같은 원리를 두 번째 사례가 다른 수치로 확인해서, 코어 칩의 "실측" 문구를 사례 2건 기준으로 바꾸는 게 맞다.
그 외에는 코어를 건드리지 않는다. 제안이 승인되면 Core 폴더의 생성 스크립트가 없을 수 있으니 `VFX 코어 이론.md`와 `VFX 코어 이론.html`의 해당 문장만 고친다.
