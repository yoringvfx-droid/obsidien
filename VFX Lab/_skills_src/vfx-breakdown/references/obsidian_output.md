# 3단계: 옵시디언에 분석 정리하기

## 폴더

```
<볼트>/Effect Breakdown/<작품 폴더명>/
├─ <작품 폴더명> - Index.md      ← 분석 노트(아래 양식)
├─ <작품 폴더명>_이펙트분해.html  ← build_page.py 결과(단일 파일)
└─ assets/                        ← 카드별 내보낸 그림 jpg
```
폴더명은 파일 시스템에 쓸 수 없는 문자(`\/:*?"<>|`, 전각 쉼표 포함)를 빼고 공백으로 바꾼다. 예: `星光啊，闪爆他` → `星光啊 闪爆他`.
기존 사례: `Effect Breakdown/星光啊 闪爆他/` (근거 코드 BD0–BD20).

**이름 규칙**
- HTML 파일명: `<짧은 이름>_이펙트분해.html`. 짧은 이름 = 제목의 앞 토큰(한자·한글 부분 또는 첫 영단어 1–2개). 예: `星光啊_이펙트분해.html`, `放晴_Heart_이펙트분해.html`.
- config `title_latin`: 제목 글자의 절반 이상이 라틴 문자면 true(세리프 한자 글꼴 대신 산세리프).

## 근거 코드

각 사례는 근거 코드 접두어를 하나 갖는다. 핸드북 카드 frontmatter `evidence`에 이 코드가 들어간다.
- 星光啊 闪爆他 = `BD0`…`BD20` (최초 사례라 접두어 없이 BD)
- 새 사례 = 대문자 2–5자 + 하이픈 + 번호. 예: `SONIC-1`, `SONIC-2`. 다른 사례와 겹치지 않게 Index frontmatter `evidence_code`에 적는다.

## 그림 내보내기

```bash
export NODE_PATH=<setup.sh가 알려준 경로>
node scripts/shoot.js export PAGE.html OUT/assets lab:<코드소문자>-01-timeline,t1:<코드소문자>-02-grammar,…
```
그림 파일명은 볼트 전체에서 겹치면 안 된다(옵시디언은 파일명으로 찾는다). `<코드소문자>-NN-<이름>` 형식을 쓴다. 내보낸 PNG는 JPG(가로 최대 1600, 품질 88)로 바꿔 assets에 둔다.
옵시디언은 HTML을 미리보기로 못 보여주므로, 핵심 카드는 전부 그림으로 내보내 Index에 넣는다.

> [!tip] 색 숫자 읽는 법
> - **명도** 0–100: 흑백으로 바꿨을 때의 밝기. 0 검정, 100 흰색. 코어 85–100 · 바디 60–85 · 엣지 35–60 · 헤이즈 22–35.
> - **선명도** 0–100 안팎: 눈에 보이는 채도. 0이면 회색, 클수록 진하다.
> - **HSV S**: 색 선택기의 채도(Saturation) 숫자. 같은 HSV S가라도 색마다 선명도가 다르다.
> - **색상** 0–360°: 색상환 위치. 0 빨강 · 60 노랑 · 120 초록 · 180 청록 · 240 파랑 · 300 자홍. 이 사례는 <주요 색 2–4개, 이름(각도)>.

Index 글에도 카드 ID만 쓰지 않고, 색 숫자는 명도·선명도·HSV S·색 이름(각도)으로 쓴다(L\*·C\*·Lab 금지, 측정 방법 줄만 예외).
Index 글에도 카드 ID만 쓰지 않는다. 카드는 `[[VA07 대비 전쟁과 주목 양보]]` 링크로(이름이 보인다), 문장 안에서는 원리를 풀어 쓴다.
HTML은 주소 끝에 `#f=154`(또는 `#f=40-46`)를 붙여 열면 그 프레임에서 시작한다. 옵시디언 링크에서 `#`이 유지되는지는 환경마다 달라서 Index 본문에는 넣지 않고, info 칸에 사용법만 한 줄 적는다.

근거 코드 표와 평가 항목은 4단계(핸드북 반영)의 재료다. 수치는 measure.py 출력 그대로 쓴다.
- 평가 항목에서 새로 잰 수치(섬광, 가림, 화면 덮음, 주목 구간 등)는 근거 코드도 새로 붙인다. 항목의 근거 줄 끝에 코드를 적는다.
- 평가 그림은 세 장: `r0` 총평(`-review`), `r1` 잘된 점(`-review-good`), `r2` 아쉬운 점(`-review-bad`).
星光啊 Index는 이 양식보다 먼저 만들어졌지만 근거 코드 표와 평가 표를 나중에 채워 두었다. 양식이 헷갈리면 이 문서의 양식을 따른다.
